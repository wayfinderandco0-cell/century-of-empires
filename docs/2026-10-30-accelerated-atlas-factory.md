# Century of Empires — accelerated atlas factory plan (2026-10-30)

**Intent:** User asks how to accelerate the approved roughly 432-octagon Europe atlas without losing the approved native Alpine landscape quality, geographically appropriate variation, sparsely placed towns, and meaningful conquest boundaries. This is an engineering plan, NOT a claim that work is finished. Existing approved-method art source commit: `456107f28c8db1f87522bbc7511809b2a215f6fb`. Initial native-canvas/manifest integration commit: `fcd58f5925ea3940fff0c6fcb662ca64f29401ef`.

## Critical acceleration decision: factory before hand-authoring any more one-off octagons
1. **Use one octagon grammar / manifest**, not hundreds of bespoke standalone HTML pages. Reuse the new `terrain-grid/atlas-cells.json` and `terrain-grid/atlas-integrated.js`; evolve both without discarding working V121/V123 or original art. Support any cell count, world-space placement, and stable IDs.
2. **Generate art in batches** from geographically appropriate height/land/river/vegetation context and a library of original or adequately licensed region-specific visual elements. Enforce seed variation, slope, channel, forest-cover and settlement density, and add selected distinctive hand-authored cells for iconic locations. No cloning of the same Matrei mountains into non-Alpine Europe. Establish verifiable sources/licenses in manifests. Honor original 1780–1880 art mood, without inventing historic topographic facts.
3. **Design an exact single route graph and border contract ahead of rendering**: shared left/right/top/bottom entrance, when present, and graph segment; a road exists only if connected to a meaningful pass, town or route, never to satisfy a decorative edge. Art generator must condition visible cartway on it. Crossing edges and rivers are reserved in all adjacent cells before either cell is built. Avoid erroneous double roads, square gap crossings, mismatched bridge ramps or terrain warping. Keep empty borders road-free. Decorative interstitial gaps have no roads or traversal.
4. **Separate scenic settlement and capturable province node/owner**, overlay province control from game state, not baked into the image. Most cells should contain countryside, roads, rivers and vegetation; sparse historical cities/ports/forts/pass points receive capture mechanics. Verify location/date before calling a town or 1780 road historic. Use configurable historical era/starting year as nation identities and borders change.
5. **Stream and cache terrain by region and four zoom levels**: thumbnail/low-res strategic tiles, medium regional tiles, full-res at town zoom. Never download or draw all ~432 1536×1024 assets on an iPhone at once. Preload immediate neighbors, unload distant textures. Reuse canonical world positions for zoom, provinces, armies, marching.
6. **Parallelize only independent work streams** under non-conflicting source files or isolation branches: A cell-asset generation, B route/terrain/road/edge validator, C gameplay territory UI, D automated browser checks. Integrate through one selected branch with a serialized gate. Avoid multiple agents pushing the same branch/files. Do not create more hourly jobs until truly useful and authorized.

## Priorities and checkable milestones
- **Gate 0 (now):** Native game-canvas three-octagon integration is committed as candidate; verify real browser workflow and unchanged campaign/saves and graph. This can progress concurrently with manifest design. Do not call production complete yet.
- **Gate 1 (first implementation priority):** One reproducible CLI/script generates cell manifests and distinctive preview images for 4 or more tiles from typed parameters/seed without copying an existing finished image; supports road entrance contracts. Add a unit test proving no repeated tile image hash, no unpaired road ports, no scenic villages treated as province captures, no false historic verification. Commit code and visual output—not only tests or planning docs.
- **Gate 2:** Build and play an **8–16 octagon** cohesive contiguous regional block on iPhone-sized WebKit and Chromium: visible road seams, pan/zoom, tap/march, neighboring lazy load, bridges only with valid art and route, 2+ different terrain subtypes. Review screenshot/contact sheet and actual preview, not synthetic metrics alone.
- **Gate 3:** Region-level prototype of **80 strategically meaningful provinces** with capture and map-controlled ownership, economy/supply and save safeguards as game actually supports. Province count is distinct from cell count. Avoid blocking terrain generation on manually certifying 80 historic settlements first; mark unverifiable names and routes as provisional, not historical.
- **Gate 4:** Render and stream an approximately **432-octagon** European visual coverage map, while improving accuracy of strategic/history-critical locations. No fictitious road connections, false dates or claimed 1780 exact routes. Clearly differentiate visual coverage from playable/prod-ready and researched history.

## Timing—conditional, not delivery guarantees
- 8–16 connected unique cells: **1–3 weeks** if the reusable system is implemented and works.
- 80-province playable regional slice: **6–12 weeks** if the existing campaign mechanics can be adapted safely.
- Roughly 432-cell European *visual coverage*: **2–4 months** if batch generation, caching and validation succeed. Geographic art quality or source licensing could extend this.
- Fully polished and historically researched game: **not covered by these accelerated targets**; accuracy and gameplay testing need additional time.
- Track actual number of cells **generated**, **visually approved**, **connected/traversable**, **loaded on mobile**, **integrated in native game**, and **historically verified** separately. No percentages without evidence.
