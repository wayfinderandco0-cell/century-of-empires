# V268 — One-source geographic terrain production path (decision record)

## Objective
Replace the failed disconnected "50 octagons/day" candidate workflow with a repeatable, native-game graphics-production pipeline. A finished tile is a correctly styled, contiguous, world-referenced terrain tile **loaded into the real iPhone game and playable where terrain permits**, with visual approval. SVG markers, scenic photo galleries, glTF exports alone, and green CI are not finished tiles.

- Protected project: `wayfinderandco0-cell/century-of-empires`, branch `terrain-v267-three-original-art-prototype-20261028`. **Never alter production/main or V94 saves** without release consent.
- Three approved WEST/MATREI/SOUTH original-art octagons and V121/V123 painted roads must stay unchanged; they are a visual/movement baseline, **not a real-world georeferenced survey** (`terrain-grid/atlas-cells.json` explicitly says fictional local study).
- Existing `generated/v267-relief-pilot`: 8 adjacent DEM-derived preview images, 8 **true glTF terrain meshes**, shared 16px heightfield, 3 infills, terrain/rock/foliage/road experiments and WebKit screenshots. Geometry seams already numerically validated; **not visually approved, not geographically suitable for Matrei local terrain, not playable**. Existing 27 source-photo tiles and 50 preview SVGs are also not complete.
- Existing `terrain-grid/atlas-integrated.js` loads original art in the real HTML Canvas game. `atlas-overland.js` provides source-bound movement safety but C03 crossing is blocked. Keep that correct fail-closed behavior.

## Architecture (do this; do not restart engines or keep remaking isolated pictures)
1. **One registered geographic world**: start a separate authentic terrain pilot *near Matrei am Brenner*, authoritative place coordinate reference ~47.1333N, 11.4667E (Getty TGN); project all geographic layers to EPSG:32632 (UTM zone 32N). Choose a fixed *ground-distance* scale for each 1536x1024 local patch, record bounding boxes, versions, meters-per-pixel and provenance. Do not use V94 Europe-wide 3.5-degree-per-cell preview heights as close-zoom ground truth. Do not claim V267 painted images were surveyed.
2. **Acquire a single continuous DEM covering the entire pilot area + margin** (e.g. Copernicus GLO-30). Derive shared height, slope, water obstacles and cliff/movement masks from this ONE dataset. Pin URL, retrieval date, license, hash, coordinate transform. Render geography once at a fixed world pixel grid; cut into 1536x1024 tile assets *after* the shared scene is composed. Thus adjoining pixels and mesh border heights are inherited, never independently guessed.
3. **One coherent art treatment**: adapt the EXISTING V267 true-heightmesh export, 3D foliage/rocks and texture materials to the new common DEM and fixed camera/sun. Approved WEST/MATREI/SOUTH determine art direction, not copy/paste foreign landforms. Bake real 3D geometry into WebP for the existing low/medium-zoom Canvas renderer; retain glTF and height/collision data for true close-zoom 3D. Scatter trees/meadows/rock using ESA WorldCover 10m as a *modern reference*; treat period vegetation as unverified unless historical evidence exists. Add non-geographic aesthetic detail procedurally only within measured terrain-class boundaries. No separate AI scenes for each tile.
4. **Octagon is an interaction polygon, not a terrain-file boundary**: draw the continuous rectangular terrain patches with octagonal selection/ownership overlays. Do NOT create blank decorative diamond gaps between octagons; the world underlay covers them. Clip an overlay if needed, never clip/copy physical ground and then invent missing infill. Same world coordinates for height, roads, units, camera, masks.
5. **Separate roads from terrain**: no guessed painted strategic roads to make edges touch. Import historical roads/towns as dated, georeferenced vectors only when evidence/rights permit (e.g., OpenHistoricalMap time-tagged features or Austrian 19th-century military survey maps). Provenance per segment; modern OSM does not prove an 1780 road. Generate visible road mesh/paint and the gameplay route graph from the SAME approved polyline in world space. Rural passability uses measured DEM slope and water/rock masks instead of demanding a road on every tile. Never enable a river crossing without verified bridge/fording evidence.
6. **Native integration**: add a versioned V268 world manifest: `id, originMeters, bboxWGS84, geoCRS, dimensionsPx, heightfield, artWebp, meshGltf, passabilityMask, waterMask, verifiedRoadIds, townIds, sourceHash, visualApproval, gameplayEnabled`. Lazy-stream visible WebP tiles in `terrain-grid/atlas-integrated.js` without replacing V94 campaign or the existing approved three. In the 3D close zoom, stream only the visible nearby glTF meshes / foliage as hardware allows.
7. **Automatic acceptance**: continuous-scene edge equality (raster and mesh), no missing polygons, water/movement correspondence, approved road graph/pixels exact, original approved art unchanged, 390x844 WebKit iPhone pan/zoom/march/return, rendered screenshots and public staging HTTP. Count finished only when all acceptance checks + visual approval pass.

## Practical build sequence
- First commit a small V268 dataset manifest and a reproducible build from **one real geographic rectangle** near Matrei, not the random SOUTH/C03 artwork seam. Show exact input data, 2x2 shared 3D relief mosaic, and one aligned source image with labels. No roads are required on road-free terrain; no historical/approval claims.
